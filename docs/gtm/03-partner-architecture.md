# 파트너 구조 설계
## smaXtec × 코리아제네틱스 × D2O × 데이터센터

> **설계 원칙**: 네 주체가 **같은 층에서 경쟁하지 않게** 만든다.
> 각자 다른 층을 소유하고, 층과 층 사이는 **인터페이스(계약 + API)로만** 만난다.
> 한 주체가 빠져도 그 층만 교체하면 되도록 — 이것이 국가 인프라의 조건이다.
>
> ⚠️ 이 문서의 금액·비율은 **협상 전 기준선(설계 예시)**이다. 확정 조건이 아니다.
> 실제 계약 시 이 표를 출발점으로 협상한다.

## 1. 한눈에 보는 4층 소유 구조

```
┌───────────────────────────────────────────────────────────────────────┐
│  L4  거버넌스 · 데이터 주권          【데이터센터 / 공공기관】           │
│      데이터 보관 · 연산 · 접근통제 · 감사 · 국가별 소버린 존             │
│      ▲ 소유: 국가·지자체 (또는 합작 SPC)                               │
├───────────────────────────────────────────────────────────────────────┤
│  L3  플랫폼 · 지능                   【D2O Corp — 주관기업】            │
│      CowTalk SW · AI 해석 · 4역할 서비스 · 공공데이터 커넥터 · MCP 도구  │
│      ▲ 소유: D2O (SW IP 100%)                                         │
├───────────────────────────────────────────────────────────────────────┤
│  L2  실행 · 유전자원                 【코리아제네틱스】                  │
│      정액·수정란 공급 · 수정사 네트워크 · 번식 시술 · 현장 실행          │
│      ▲ 소유: KG (유전자원 IP · 시술 네트워크)                          │
├───────────────────────────────────────────────────────────────────────┤
│  L1  센싱 · 하드웨어                 【smaXtec】                        │
│      위내 볼루스 · 기지국 · 이벤트 엔진(발정·분만·질병)                  │
│      ▲ 소유: smaXtec (센서 IP · 이벤트 알고리즘)                       │
└───────────────────────────────────────────────────────────────────────┘
```

**읽는 법**: 아래층은 위층에 **원천**을 공급하고, 위층은 아래층에 **수요**를 만들어준다.
CowTalk이 "이 소에 이 정액"이라고 추천할 때마다 KG의 매출이 생기고,
CowTalk이 농가를 늘릴 때마다 smaXtec의 센서가 팔린다.
**플랫폼이 파트너의 영업사원이 되는 구조** — 이것이 이 설계의 핵심이다.

## 2. 주체별 역할·기여·회수

### 2-1. smaXtec — 센싱 레이어 (Austria)

| 항목 | 내용 |
|---|---|
| **역할** | 위내 볼루스 센서, 농장 기지국, 검증된 이벤트 엔진 공급 |
| **CowTalk에 주는 것** | 체온·활동량 원시 데이터, 발정/분만/질병 이벤트, 개체 마스터 데이터 |
| **CowTalk이 주는 것** | 한국·수출시장 판매 채널, 한국형 부가가치로 인한 **센서 잔존율(retention) 상승** |
| **계약 형태** | 총판/OEM 공급계약 + Integration API 접근 계약 |
| **회수 구조** | 하드웨어 판매 마진 + 센서 구독료(두당) |
| **데이터 방향** | smaXtec → CowTalk **단방향 수신**. 역방향 동기화 없음 |

**전략적 주의 — 단일 공급자 종속(vendor lock-in) 리스크**

이 구조의 가장 큰 취약점이다. 솔직하게 인정하고 설계로 방어한다.

1. **센서 추상화 레이어**: 커넥터 패턴(`AbstractConnector`)으로 센서 벤더를 추상화.
   다른 벤더(Allflex, CowManager, 국산 센서)를 커넥터 추가만으로 붙일 수 있는 구조 유지.
2. **원시 데이터 자체 적재**: 이벤트만 받지 않고 **원시 측정치를 우리 DB에 축적**한다.
   벤더가 바뀌어도 과거 데이터와 학습 자산은 우리 것으로 남는다.
3. **이벤트 재현 능력 확보**: 자체 조기감지 엔진(DSI)을 병행 운영해
   벤더 이벤트 없이도 최소 기능이 성립하게 한다. (현재 구현됨)
4. **계약 조항**: API 접근 최소보장 기간, 가격 인상 상한, 데이터 반출권 명시.

> **발표 시 표현**: "센서는 세계 최고를 씁니다. 다만 우리는 **센서에 종속되지 않도록**
> 추상화 계층을 두었습니다. 국산 센서로 바꿔야 할 정책적 필요가 생기면 커넥터만 바꿉니다."

### 2-2. 코리아제네틱스 — 수입 + 실행·유전자원 레이어

| 항목 | 내용 |
|---|---|
| **역할** | **smaXtec 수입·통관·유통(현행 주 역할)** + 정액·수정란 공급, 수정사 네트워크, 현장 번식 시술 |
| **CowTalk에 주는 것** | 종모우 유전정보 카탈로그, 정액 재고, **수정 결과 데이터(수태 성공/실패)** |
| **CowTalk이 주는 것** | **수정적기 추천 → 시술 발주로 직결되는 수요 파이프라인**, 수태율 실측 피드백 |
| **계약 형태** | 유전자원 공급 + 시술 실행 파트너십 (+ 옵션: 국내 채널 총판) |
| **회수 구조** | **센서 수입 마진(두당 월 7,700원 중 약 1,480원 추정)** + 정액 판매 + 수정 시술료 |

**왜 이 파트너가 구조적으로 중요한가**

번식 AI는 **추천만 하면 반쪽**이다. "내일 06시 수정적기, 추천 정액 KPN1234"라고 말해도
그 정액이 목장에 없고 시술할 사람이 없으면 아무 일도 일어나지 않는다.
KG는 **추천을 실물로 바꾸는 유일한 층**이다.

그리고 결정적으로 — **수정 결과가 돌아와야 AI가 학습한다.**
수정 → 임신감정 → 결과 피드백 루프에서 KG는 데이터 생산자이기도 하다.

| 루프 단계 | 주체 | 산출 |
|---|---|---|
| 발정 감지 | smaXtec | 발정 이벤트 |
| 수정적기 계산 · 정액 추천 | CowTalk(D2O) | 추천 카드 |
| 정액 공급 · 시술 | **코리아제네틱스** | 수정 기록 |
| 임신감정 | 수의사 / KG | 임신 여부 |
| 학습 반영 | CowTalk(D2O) | 정액별·개체별 수태율 갱신 |

**⚠️ 이해상충 방지 조항 (반드시 계약에 명시)**

정액 추천 AI가 특정 공급사 제품을 편향 추천하면 플랫폼의 신뢰가 무너진다.
공공 플랫폼을 지향한다면 이 지점을 먼저 봉인해야 한다.

- 추천 알고리즘은 **근교계수·유전능력·목장 목표**만으로 순위를 매긴다 (공급사 가중치 금지)
- 추천 결과에 **공급사를 표시하고, 대안 정액을 항상 함께 제시**한다
- 추천 로직과 근거는 **감사 가능**해야 한다 (알고리즘 공개 수준의 설명 제공)
- 지자체·국가 사업에서는 **복수 공급사 등록을 개방**한다

> 이 조항이 있어야 "특정 회사 밀어주기 아니냐"는 심의 질문을 한 문장으로 넘긴다.

### 2-3. 농업회사법인 주식회사 디투오 — 플랫폼 · 영업 · 교육 (주관기업)

| 항목 | 내용 |
|---|---|
| **역할** | CowTalk 플랫폼 · AI 해석 엔진 · 공공데이터 연동 · **영업** · **교육** · 자사 영업 고객 대상 **센서 공급** |
| **조직** | **1인 영업 체제(기술이사)** — 실행은 파트너·외주로 분산하는 asset-light 구조 |
| **소유 자산** | **SW IP 100%**, AI 프롬프트·학습 자산, 커넥터/MCP 도구 체계, 운영 노하우 |
| **회수 구조** | ① 농가 SaaS 구독 ② 지자체·국가 라이선스 ③ 구축(SI) ④ 해외 로열티 ⑤ 데이터 인텔리전스 |
| **책임** | SLA, 보안, 감사로그, 데이터 거버넌스 준수, 현지화 어댑터 |

**D2O가 반드시 지켜야 할 경계선**

- **하드웨어를 직접 만들지 않는다** — 센서는 잘하는 곳에 맡긴다
- **유전자원을 직접 팔지 않는다** — 이해상충의 씨앗
- **데이터를 소유하지 않는다** — 원천 데이터의 주인은 농가·국가다 (§4 참조)
- **데이터센터를 직접 운영하지 않는다** — 외주. 보관 주체와 운영 주체를 분리하는 설계와도 맞는다
- **설치 인력을 직접 고용하지 않는다** — 시공 파트너를 **교육해서** 확장한다

D2O는 **얇지만 대체 불가능한 층**을 갖는다. 이것이 SW 회사가 인프라 사업에서 살아남는 유일한 포지션이다.

> **확장 원리**: 직접 고용하면 커버리지가 **덧셈**으로 늘고, 파트너를 교육하면 **곱셈**으로 늘어난다.
> D2O가 교육을 자기 역할로 잡은 이유가 이것이다. 📎 [`04-education-curriculum.md`](04-education-curriculum.md)

> ⚠️ **1인 의존(key person) 리스크는 실재한다.** 심의에서 반드시 나온다.
> 대응은 ① 플랫폼 자동화 ② 실행 파트너 계약 문서화 ③ 매출 연동 단계적 채용 계획.
> 📎 [`14-cost-structure.md`](14-cost-structure.md) §3-4

### 2-4. 데이터센터 — 거버넌스·주권 레이어 ⚠️ **운영사 미정**

| 항목 | 내용 |
|---|---|
| **역할** | 데이터 보관·연산·백업, 접근통제, 감사, 국가별 소버린 존 운영 |
| **수행 방식** | **외주.** D2O는 계약·감독·거버넌스만 담당하고 직접 운영하지 않는다 |
| **현재 상태** | **운영 업체 미선정 · 데이터 주권 귀속 미합의** — 계약·심의·수출의 전제이므로 최우선 과제 |
| **소유(안)** | 국내: 지자체/공공기관 위탁 또는 합작 SPC · 해외: 해당 국가 지정 인프라 |
| **회수 구조** | 인프라 이용료(두수·용량 기반), 공공 예산 편성 |
| **핵심 기능** | "데이터가 국경 밖으로 나가지 않는다"를 **기술적으로 보장** |

**왜 데이터센터를 별도 주체로 세우는가**

이건 기술 선택이 아니라 **정치적·제도적 설계**다.

1. **국내**: 축산 데이터는 방역 정보이자 개인(농가) 사업 정보다.
   민간 SW 회사 서버에 국가 방역 데이터가 쌓이는 구조는 심의를 통과하기 어렵다.
   **데이터 보관 주체와 SW 운영 주체를 분리**하면 이 문제가 사라진다.
2. **해외**: 대부분의 국가가 데이터 현지화(data localization)를 요구한다.
   소버린 존 구조가 **수출의 전제조건**이다.
3. **신뢰**: 농가가 "내 목장 데이터를 회사가 가져간다"고 느끼는 순간 도입이 멈춘다.
   보관 주체가 공공이면 이 저항이 사라진다.

**데이터센터 구성 (권장)**

```
┌── 소버린 존 (국가/지자체 경계) ──────────────────────────┐
│                                                          │
│  [원천 데이터 저장소]      [연산·AI 추론]    [감사·통제]   │
│   센서 시계열             모델 서빙          접근로그      │
│   개체 마스터             배치 파이프라인     권한 정책     │
│   진료·처방 기록          집계 뷰            반출 승인     │
│                                                          │
│  ── 반출 경계 ────────────────────────────────────────   │
│   나가는 것: 익명화·집계 통계만 (개체 식별정보 불가)        │
│   나가지 않는 것: 원시 센서, 농가 식별정보, 진료기록        │
└──────────────────────────────────────────────────────────┘
         │ 승인된 집계만
         ▼
   [글로벌 학습 자산]  ← 국가별 모델 개선 성과를 익명 통계로만 환류
```

> 그래서 협상할 것은 **볼륨 구간별 구독료 인하**와 **해지 시 설치 센서 처리 조건** 둘뿐이다.

> **지금까지 이 모든 비용을 목장이 전액 부담했다.**
> 보조금 없이 팔린 실적이라는 뜻이고, 이건 지자체 심의에서 **가장 강력한 시장 검증 증거**다.

**추가 수익 (구독료와 별도)**

| 항목 | 귀속 | 비고 |
|---|---|---|
| 통신중계기·설치비 | 시공 주체 | 목장당 500만원 (1회) |
| 정액·수정란 판매 | 코리아제네틱스 | 플랫폼 추천 전환 수수료 배분 협의 |
| **플랫폼 구축·운영 (SI)** | **D2O** | 지자체·국가 플랫폼. **구독과 이중과금 금지** |
| 거점 대동물병원 모듈 | D2O | 병원 월 30만 + 담당농가 월 2만 |
| 해외 국가 라이선스 | D2O 로열티 | 현지 파트너 배분 별도 |

> **협상 포인트**: 수입 단가 7,700원이 매출의 **64.2%**를 가져간다.
> D2O 구독 공헌이익은 2,450원(20.4%)이고, 설치 마진을 더하면 3,194원(26.6%)이다.
> **볼륨 구간별 단가 테이블(volume tier)**을 계약에 넣는 것이 최우선 과제다 —
> 단가를 10% 낮추면 두당 800원이 생기고, 그것이 **채널 수수료 재원**이 된다.
> 순서는 **볼륨 → 단가 인하 → 채널 구축**이다.
> 📎 원가 분해·손익·협상 문장: [`14-cost-structure.md`](14-cost-structure.md)

## 4. 데이터 소유권 — 가장 먼저 합의해야 할 것

**원칙: 데이터의 층마다 주인이 다르다.**

| 데이터 계층 | 소유자 | 사용 권한 | 반출 |
|---|---|---|---|
| **원시 센서 측정치** | 농가 | 플랫폼: 서비스 제공 목적 사용 허가 | ✗ |
| **개체 마스터(이력·혈통)** | 국가 공공데이터 | 공공데이터 이용약관 준수 | 약관 범위 |
| **진료·처방 기록** | 농가 + 수의사(작성자) | 법정 보존 의무 준수 | ✗ |
| **AI 해석 결과** | 플랫폼(D2O) 공동 | 농가 열람권 보장 | ✗ |
| **전문가 레이블** | 플랫폼(D2O) | 익명화 후 학습 자산 | 익명 집계만 |
| **지역·전국 집계 통계** | 공공(지자체·국가) | 정책·연구 활용 | ○ (공개 가능) |

**합의문에 반드시 들어갈 4개 문장**

1. 농가는 **언제든 자기 데이터를 내보내고 삭제 요청**할 수 있다. (내보내기 기능 구현됨)
2. 플랫폼은 원시 데이터를 **서비스 제공 목적 외로 사용하지 않는다.**
3. 제3자 제공은 **농가 옵트인 + 익명화 + 집계** 세 조건을 모두 만족할 때만 가능하다.
4. 계약 종료 시 데이터는 **농가/국가에 반환**되고 플랫폼 사본은 파기된다.

> 이 4문장이 없으면 지자체 심의도, 해외 정부 계약도 통과하지 못한다.
> **가장 먼저 쓰고, 가장 크게 보여줘야 하는 조항이다.**

## 6. 거버넌스 — 누가 무엇을 결정하는가

| 의사결정 | 결정 주체 | 협의 |
|---|---|---|
| 제품 로드맵·기능 우선순위 | D2O | 파트너 분기 협의체 |
| 센서 하드웨어 사양·가격 | smaXtec | D2O 볼륨 협상 |
| 정액 카탈로그 등록 기준 | 공동 위원회 | **단일 공급사 독점 금지** |
| 데이터 반출 승인 | 데이터센터 운영주체(공공) | D2O 기술 자문 |
| AI 판단 기준 변경 | D2O + 전문가 자문단(수의사) | 변경 이력 감사 공개 |
| 국가별 진출 | D2O + 현지 파트너 | 정부 승인 필요시 우선 |

**전문가 자문단(Clinical Advisory Board)을 반드시 둔다.**
AI가 임상 판단에 개입하는 순간, "누가 이 기준을 정했나"에 답할 수 있어야 한다.
수의사·연구자로 구성된 자문단이 판단 기준을 검토하고 그 회의록이 감사 자산이 된다.
→ 이것이 [`05-vet-hub-hospital.md`](05-vet-hub-hospital.md)의 거점 대동물병원과 직접 연결된다.
