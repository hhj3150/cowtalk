# 지역거점 대동물병원 × CowTalk
## 시범사업 연계 모듈 설계

> **한 문장**: 정부가 지역거점 대동물병원을 세운다면, CowTalk은 그 병원의
> **임상 운영체제(Clinical OS)**가 된다. 건물과 장비만으로는 수의사가 늘지 않는다.
> **한 명의 수의사가 감당할 수 있는 농가 수를 늘려야** 거점이 작동한다.

---

## 1. 문제 정의 — 왜 거점병원만으로는 부족한가

### 1-1. 대동물 임상이 무너지는 구조

| 문제 | 실제 현장 | 결과 |
|---|---|---|
| **수의사 절대 부족** | 신규 수의사 대부분 반려동물로 유입 | 대동물 임상 고령화·공백 |
| **이동 시간이 진료 시간보다 길다** | 왕진 1건에 왕복 1~2시간 | 하루 진료 가능 건수 제한 |
| **정보 없이 출발한다** | 도착해서야 상태 파악 | 재방문·오진단 위험 |
| **야간·주말 공백** | 응급 대응 체계 부재 | 골든타임 상실 |
| **기록이 종이에 남는다** | 진료부·처방전 수기 | 이력 단절, 휴약 관리 부실 |
| **경험이 개인에게 갇힌다** | 은퇴하면 노하우가 사라짐 | 세대 전승 실패 |

### 1-2. 거점병원 정책의 구조적 한계

거점 대동물병원 시범사업은 **시설과 인력을 한 곳에 모으는** 정책이다. 옳은 방향이다.
그러나 두 가지가 해결되지 않으면 거점은 "먼 병원"이 될 뿐이다.

1. **거점이 멀어질수록 접근성은 떨어진다.** 물리적 집중은 물리적 거리를 만든다.
2. **한 명이 볼 수 있는 농가 수가 그대로면**, 거점을 만들어도 총 진료 역량은 늘지 않는다.

> **핵심 통찰**:
> 거점병원이 성공하려면 **거점에 안 가고도 진료 판단이 시작되어야 한다.**
> 즉, **원격 트리아지(triage)**가 전제 조건이다.
> 그리고 원격 트리아지는 **소의 몸속 데이터가 있어야만** 가능하다.

## 2. CowTalk이 거점병원에 제공하는 것

### 2-1. 진료 전 — "출발하기 전에 이미 알고 있다"

| 기능 | 하는 일 | 구현 상태 |
|---|---|---|
| **케이스 큐** | 담당 농장 **전체**에서 위험 개체를 자동 트리아지해 우선순위 큐로 제시 | ✅ `CaseQueuePage` |
| **조기감지 DSI** | 질병징후지수 0~100, 70 이상 자동 경보 (임상증상 이전 단계) | ✅ `disease-detection.engine` |
| **왕진 스케줄** | 위험도 × 지리 최적화로 하루 동선 구성 | ✅ `VisitSchedulePage` |
| **개체 사전 브리핑** | 도착 전 센서 추이·이력·기존 처치·산차·DIM 요약 | ✅ 개체 프로필 + 온톨로지 그래프 |

> **이것이 정책 지표를 바꾼다.**
> "수의사 1인이 담당 가능한 농가 수"가 늘어난다. 거점병원 사업의 성과 지표가 바로 이것이다.

### 2-2. 진료 중 — "AI가 진단하지 않는다. 감별을 돕는다"

| 기능 | 하는 일 | 구현 상태 |
|---|---|---|
| **감별진단** | 6개 질병 확률 순위 + **센서 근거 테이블(✓/✗/—)** + 확인검사 트리 + 긴급도 | ✅ `differential-diagnosis.service` |
| **불확실성 보정** | 근거가 약한 단일 후보가 100%로 부풀지 않도록 prior 보정 | ✅ 구현됨 |
| **치료결과 학습 가중치** | 과거 이 농장·이 질병의 치료 결과를 확률에 반영 | ✅ `loadTreatmentOutcomeWeights` |

**⚠️ 표현 규칙 (수의계 발표에서 절대 어기지 말 것)**

| ❌ 하지 말 것 | ✅ 이렇게 말한다 |
|---|---|
| "AI가 진단합니다" | "AI가 **감별 후보와 근거를 정리**합니다. 진단은 수의사가 합니다" |
| "정확도 95%" | "센서 이벤트 정확도는 제조사 성능이고, 우리는 **근거를 보여줍니다**" |
| "수의사를 대체" | "수의사 한 명의 **커버리지를 넓힙니다**" |

**설명가능성이 전부다.** 확률만 던지는 AI는 수의사가 절대 쓰지 않는다.
CowTalk은 **왜 그 확률인지 근거 항목별로 ✓/✗/—로 보여준다.**
수의사는 근거를 보고 동의하거나 기각한다. 그 기각조차 학습 자산이 된다.

### 2-3. 진료 후 — "기록이 자동으로 남고, 다음을 만든다"

| 기능 | 하는 일 | 구현 상태 |
|---|---|---|
| **처방전 PDF** | 처방 문서 자동 생성 | ✅ `prescription-pdf.service` |
| **휴약기간 자동 계산** | 약제별 휴약일 계산 → 출하·집유 안전 관리 | ✅ `withdrawal-calculator` |
| **치료 기록** | 진단·투약·경로·용량·임상소견 구조화 저장 | ✅ `record_treatment` |
| **치료결과 자동 추적** | 치료 후 센서를 다시 읽어 회복/악화/관찰 자동 판정 (24h 배치) | ✅ `treatment-outcome.service` |
| **전문가 레이블** | 수의사의 판단이 곧 학습 정답 레이블이 됨 | ✅ `record_expert_label` |

**휴약기간이 왜 정책적으로 중요한가**

항생제 잔류는 식품안전 문제이자 통상 문제다. 수기 관리로는 누락이 생긴다.
CowTalk은 처방 시점에 휴약 종료일을 계산해 **출하·집유 금지 기간을 자동으로 표시**한다.
→ 이건 농가 편의가 아니라 **국가 식품안전 관리 체계의 디지털화**다.
→ 수출 축산물 안전성 입증에도 직결된다.

### 2-4. 지역 차원 — "공수의사 업무가 여기서 만난다"

거점병원 수의사는 상당수가 **공수의사(공무직 방역 업무 위탁)**를 겸한다.
CowTalk은 이 두 역할을 한 계정에서 처리한다.

| 기능 | 하는 일 | 구현 상태 |
|---|---|---|
| 집단 발열 탐지 | 농장 단위 이상 징후 클러스터 자동 감지 | ✅ 방역 대시보드 |
| 접촉망 추적 | 실제 이동이력 기반 접촉 개체 추적 | ✅ `contact-tracer` |
| 확산 시뮬레이션 | SEIR 미분방정식 기반, 이동제한 시나리오 비교 | ✅ `spread-simulator` |
| 역학조사 워크플로 | 6항목 자동수집 + DB 영속화 | ✅ `investigations` |
| KAHIS 보고 | draft → submitted 상태 관리 | ✅ `kahis_reports` |

## 3. 거점병원 운영 모델 — 하루가 어떻게 바뀌는가

### Before (현재)

```
08:00  전화 옴 — "우리 소가 밥을 안 먹어요"
09:30  출발 (편도 40분)
10:10  도착 — 그제서야 상태 파악 시작
10:40  진단·처치, 종이 진료부 작성
11:20  다음 농장으로 이동 (40분)
...
18:00  하루 4~5건. 기록은 사무실 돌아와서 정리
       → 휴약 관리는 농가 기억에 의존
```

### After (CowTalk 연계)

```
07:30  케이스 큐 확인 — 담당 30농가에서 위험 개체 6두 자동 정렬
       · 3농가 A목장 423번: DSI 82, 체온 상승 36시간 지속, 반추 급감 → 긴급
       · 나머지 5두: 관찰 등급
07:40  왕진 경로 자동 구성 (위험도 × 동선)
07:45  A목장 농가에 사전 지시 (전화/알림톡) — 격리·보온·급수 확인
08:20  출발 — 이동 중 개체 브리핑 확인 (이력·산차·이전 치료·센서 추이)
09:00  도착 — 감별진단 후보 3개와 근거를 이미 검토한 상태로 진입
09:20  처치 + 앱에서 처방 입력 → 처방전 PDF·휴약 종료일 자동 생성, 농가에 즉시 전송
09:35  다음 농장 (경로 최적화됨)
...
17:00  하루 7~8건. 기록은 이미 끝나 있음
익일    치료결과 자동 추적 — 센서로 회복 여부 판정, 악화 시 자동 알림
```

**변화의 크기**

| 지표 | Before | After (목표) |
|---|---:|---:|
| 일 진료 건수 | 4~5건 | 7~8건 |
| 담당 가능 농가 | 15~20호 | 30~40호 |
| 기록 완결률 | 낮음 (사후 정리) | 100% (현장 완결) |
| 휴약 관리 | 농가 기억 | 시스템 자동 |
| 야간 공백 | 전화 대기 | 원격 트리아지 + 자동 경보 |

> ⚠️ 위 "After" 수치는 **설계 목표치**이며 파일럿 실측 대상이다.
> 발표에서는 반드시 "시범사업으로 검증할 목표 지표"라고 말한다.

## 4. 시범사업 설계안 (정부 제안용)

### 4-1. 사업 개요

| 항목 | 내용 |
|---|---|
| **사업명** | 지역거점 대동물병원 디지털 임상지원 시범사업 |
| **기간** | 12개월 (준비 2 + 운영 9 + 평가 1) |
| **규모** | 거점병원 3곳 × 담당 농가 각 30호 = 90농가 |
| **대상 축종** | 낙농(젖소) 우선 → 한우 확대 |
| **예산 주체** | 중앙정부 시범사업비 (병원 부담 0) |

### 4-2. 단계

| 단계 | 기간 | 내용 |
|---|---|---|
| **1. 준비** | M1~M2 | 병원 선정, 농가 모집, 센서 설치, 계정·권한 세팅, 교육 |
| **2. 기준선 측정** | M3 | 개입 전 지표 측정 (진료건수·리드타임·기록률) |
| **3. 운영** | M4~M11 | 케이스 큐 기반 진료, 월간 리뷰 |
| **4. 평가** | M12 | 전후 비교, 확산 설계 |

### 4-3. 성과 지표 (사전 합의 필수)

| 구분 | 지표 | 측정 방법 |
|---|---|---|
| **커버리지** | 수의사 1인당 담당 농가 수 | 시스템 자동 집계 |
| **효율** | 일 진료 건수, 이동거리/건 | 왕진 기록 |
| **조기성** | 증상 발현 대비 개입 리드타임 | DSI 경보일 vs 진료일 |
| **품질** | 치료 성공률(회복 판정 비율), 재발률 | 치료결과 자동 추적 |
| **안전** | 휴약기간 준수율, 처방 기록률 | 시스템 자동 |
| **방역** | 이상징후 조기 인지 건수 | 방역 대시보드 |
| **만족** | 농가·수의사 NPS | 설문 |

> **가장 강력한 단 하나의 지표**: **"증상 발현 대비 개입 리드타임"**
> 며칠 빨리 발견했는가. 이 수치 하나가 시범사업의 성패를 설명한다.

### 4-4. 예산 구조 (기준선, 3개 병원 12개월)

| 항목 | 산출 | 금액 |
|---|---|---:|
| 센서·기지국 구축 | 90농가 × 500만원 | 4.5억 |
| 플랫폼 이용료 | 90농가 평균 60두 × 15,000원 × 12개월 | 9.7억 |
| 병원 임상모듈 | 3곳 × 30만원 × 12개월 | 0.11억 |
| 교육·운영 지원 | — | 0.5억 |
| 평가·연구 | 대학·연구기관 위탁 | 0.4억 |
| **합계** | | **약 15.2억** |

> 규모는 조정 가능하다. 핵심은 **비용 구조가 투명하고 지표가 사전 합의된다**는 점이다.

## 5. 수의계 설득 논리 — 가장 중요한 3분

수의사는 **AI에 대한 경계심이 가장 큰 전문가 집단**이다. 당연하다.
오진의 책임을 지는 사람이 그들이기 때문이다. 이 3가지를 순서대로 말한다.

### ① 책임의 경계를 먼저 그린다

> "**최종 판단과 처방은 수의사의 권한이며, 시스템은 이를 대신하지 않습니다.**
> CowTalk은 근거를 정리해 드리는 도구입니다.
> 모든 AI 판단은 감사 로그에 남고, 수의사의 승인 없이 실행되는 처치는 없습니다."

실제로 이렇게 구현되어 있다 — 승인 게이트(`APPROVAL_REQUIRED_TOOLS`),
감사 로그(`tool_audit_log`), 역할별 접근 통제(RBAC).
**자동화 룰 엔진조차 승인 체계를 우회하지 않는다.**

### ② 대체가 아니라 증폭임을 숫자로 보인다

> "수의사를 줄이는 게 아니라, **한 분이 30호를 볼 수 있게** 만듭니다.
> 지금 대동물 수의사가 부족한 게 문제지, 많은 게 문제가 아니지 않습니까."

### ③ 전문가의 지식이 자산이 되는 구조를 보여준다

> "선생님이 '이건 케토시스네'라고 판단하시면, 그 판단이 학습 레이블이 됩니다.
> **농장주나 행정관의 추측은 학습에서 제외됩니다** — 전문가 판단만 정답으로 씁니다.
> 은퇴하시면 사라지던 노하우가, 시스템에 남아 다음 세대가 씁니다."

이것이 CowTalk의 가장 강력한 수의계 세일즈 포인트다.
**"당신의 경험이 데이터 자산이 된다."**

## 6. 거점병원 × 방역 — 정책적으로 가장 큰 그림

거점 대동물병원은 임상 기관이면서 동시에 **방역의 지역 노드**다.
CowTalk은 이 둘을 하나로 잇는다.

```
     [농가 센서]  ──── 이상징후 ───▶  [거점병원 케이스 큐]
          │                                  │
          │                            임상 판단·처치
          │                                  │
          │                                  ▼
          └──── 집단 이상 ───▶  [지역 방역 상황판] ───▶ [시도·전국]
                                        │
                                  역학조사 · 접촉망
                                  확산 시뮬레이션
                                        │
                                        ▼
                                   [KAHIS 보고]
```

**의미**: 지금까지 방역은 **농가 신고 → 행정 확인 → 검사**의 순서였다.
CowTalk 연계 거점병원 체계에서는 **센서 이상 → 수의사 임상 확인 → 방역 판단**이
같은 시스템 안에서 일어난다.

> **국가 발표용 한 줄**:
> "거점 대동물병원은 진료소이자 **방역 초소**가 됩니다.
> 임상 데이터와 방역 데이터가 처음으로 같은 화면에서 만납니다."

---

## 7. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 수의사의 AI 거부감 | 설명가능성 노출, 책임 경계 명시, 전문가 자문단 참여 |
| 진료 기록의 법적 지위 | 전자진료부 관련 규정 사전 검토, 원본 보존 정책 |
| 원격 판단의 책임 소재 | "원격 트리아지 ≠ 원격 진료" 명확 구분. 진단은 대면 원칙 |
| 병원 지불 여력 부족 | 시범사업 예산이 결제 (병원 부담 0 설계) |
| 농가·병원 간 데이터 접근 범위 | 담당 배정된 농장만 조회 — 게이트웨이 수준 강제 (구현됨) |
| 센서 미설치 농가 | 거점병원 도구는 센서 없이도 기본 기능 제공 (기록·처방·휴약) |

> **"원격 트리아지 ≠ 원격 진료"** — 이 구분은 반드시 명시한다.
> CowTalk이 하는 것은 **누구를 먼저 볼지 정하는 것**이지 원격으로 진단하는 것이 아니다.
> 이 한 줄이 규제 리스크의 대부분을 정리한다.
