# CowTalk v5 소개서
## 축산 디지털 운영체제 (Livestock Digital Operating System)

> **한 문장**: CowTalk은 소의 몸속 센서가 보내는 신호를 국가 공공데이터·AI와 결합해
> **농가·수의사·방역관·행정이 각자의 언어로 "지금 무엇을 해야 하는지"를 받는 플랫폼**입니다.

---

## 1. 왜 지금인가 — 축산이 마주한 세 개의 벽

### 벽 1. 사람이 사라지고 있다
축산 현장의 고령화는 통계가 아니라 현실이다. 대동물 수의사는 더 심각하다.
새로 배출되는 수의사 대부분이 반려동물로 가고, 왕진 한 번에 왕복 2시간을 쓰는
대동물 임상은 지원자가 줄고 있다. **사람이 줄어드는 속도를 기술이 따라잡지 못하면
축산은 관리 불능 상태가 된다.**

### 벽 2. 질병은 항상 "늦게" 발견된다
소는 아프다고 말하지 않는다. 눈에 보일 때는 이미 늦다.
구제역·럼피스킨 같은 악성 전염병은 **첫 신고 시점에 이미 확산이 시작된 상태**다.
방역은 사후 대응의 반복이 된다.

### 벽 3. 데이터는 있는데 연결되지 않는다
이력제, 등급판정, DHI, KAHIS, 기상 데이터가 모두 존재한다.
그런데 **농가 한 사람이 이 데이터를 자기 소 한 마리에 연결해서 판단하는 일은
현실적으로 불가능**하다. 데이터는 있지만 의사결정에 닿지 않는다.

---

## 2. CowTalk의 답 — "알람"에서 "행동"까지 다리를 놓는다

세계 최고 수준의 위내(反芻胃) 센서는 이미 존재한다. 오스트리아 smaXtec의 볼루스는
소의 위 속에서 체온·활동량·음수를 측정해 발정·분만·질병 징후를 잡아낸다.

**그런데 센서는 여기까지다.** 알람이 울려도 목장주는 혼자 판단해야 한다.
"발정입니다"라는 알림 뒤에 "그래서 언제 수정하고, 어떤 정액을 쓰고,
이 소는 지난달 유방염 치료했는데 괜찮은가"는 아무도 알려주지 않는다.

> **CowTalk은 이 간극을 메운다.**
> 알람 → 판단 → 추천 → 행동 → 기록이 **한 화면에서 끝난다.**

### 핵심 공식

```
smaXtec 위내센서  +  국가 공공데이터  +  AI 해석  +  역할별 액션플랜  =  CowTalk
   (몸속 신호)        (이력·혈통·등급)     (맥락 판단)    (누가 뭘 하나)
```

## 3. 4층 구조 — 어떻게 작동하는가

```
┌──────────────────────────────────────────────────────────────┐
│  4층 · Intelligence Loop  — 쓸수록 똑똑해진다                  │
│  피드백 → 정확도 추적 → 프롬프트 자기보정 → 전문가 레이블 축적    │
├──────────────────────────────────────────────────────────────┤
│  3층 · Role-Based Serving — 같은 데이터, 4개의 관점            │
│  농가 / 수의사 / 방역관 / 행정  각자의 대시보드와 액션플랜        │
├──────────────────────────────────────────────────────────────┤
│  2층 · AI Interpretation — 맥락으로 해석한다                   │
│  통합 프로필 → LLM 해석 + 룰엔진 보조 → 설명가능한 판단          │
├──────────────────────────────────────────────────────────────┤
│  1층 · Data Integration — 흩어진 것을 한 마리에 모은다          │
│  센서 이벤트 + 공공데이터(이력·등급·경락) + 농장기록 + 기상       │
└──────────────────────────────────────────────────────────────┘
```

### 1층 — 한 마리의 소에 네 개의 번호를 붙인다

한국의 소 한 마리에는 최대 네 개의 번호가 존재하고, 지금까지 이들은 **서로 다른 시스템에
따로 살고 있었다.** CowTalk은 이것을 한 개체로 묶는다.

| 번호 | 발급 | CowTalk 역할 |
|---|---|---|
| 이력제 번호 (12자리) | 국가 (출생 2주 내) | 공공데이터 조회 키 |
| 목장 관리번호 | 농장 자체 | 현장에서 부르는 이름 |
| 혈통등록번호 | 종축개량협회 | 근교계수·유전능력 |
| 센서 시리얼 | smaXtec | 실시간 생체신호 |

**이 결합이 CowTalk의 기술적 해자(moat)다.** 센서만으로는 "이 소가 열이 난다"까지밖에
못 간다. 이력·혈통·등급·시세가 붙어야 "이 소는 3산차 고능력우인데 지난 유방염 이력이
있고 지금 열이 나므로 우선순위 1번, 예상 손실 X원"이 된다.

### 2층 — AI가 재판단하지 않고, 해석한다

원칙 하나를 정확히 지킨다: **센서 제조사가 검증한 이벤트는 재판단하지 않는다.**
발정 탐지 정확도는 smaXtec이 확보한 성능이고, CowTalk이 그걸 다시 뒤집으면
정확도만 떨어진다. CowTalk이 하는 일은 **그 이벤트에 맥락을 붙이는 것**이다.

- 모든 판단에 `explanation`(왜 그렇게 봤는지) + `contributingFactors`(근거 목록) 필수
- AI 응답에 **출처(data_references) 기록 의무** — 근거 없는 문장은 만들지 않는다
- AI 장애 시 룰 엔진이 자동으로 대체 분석 수행 (서비스 중단 없음)

### 3층 — 같은 데이터를 4개 역할이 각자의 관점으로

| 역할 | 보는 것 | 받는 것 |
|---|---|---|
| **농장주** | 내 소 한 마리 | 오늘 할 일, 발정·분만 알림, 두당 마진 |
| **수의사** | 담당 목장 여러 개 | 위험 개체 트리아지, 감별진단, 왕진 동선 |
| **방역관** | 지역 전체 | 집단 발열, 접촉망, 확산 시뮬레이션 |
| **행정** | 시도·전국 | 수급, 정책 브리핑, 예산 근거 |

**같은 한 마리의 소가, 보는 사람에 따라 다른 의미를 갖는다.**
농가에겐 "내일 수정할 소", 방역관에겐 "3km 반경 접촉 개체", 행정관에겐 "통계 1건".
CowTalk은 이 네 관점을 하나의 데이터 척추(Data Spine) 위에 세운다.

### 4층 — 쓸수록 정확해진다

이건 마케팅 문구가 아니라 구현된 구조다.

- **전문가 레이블 루프**: 수의사가 대화 중 "이건 케토시스네"라고 판단하면
  그 문장이 학습 레이블이 된다. (**전문가 역할만** — 추측이 학습 데이터를 오염시키지 않도록)
- **프롬프트 자기보정**: 알람별 오탐/확진 통계를 집계해 AI에게 주는 지침을 자동 생성.
  단, **라벨 10건 미만이면 생성 금지** — 표본 부족한 통계로 AI를 바꾸지 않는다.
- **치료 결과 추적**: 치료 후 센서를 다시 읽어 회복/악화를 자동 판정하고 다음 판단에 반영.

## 4. 지금 실제로 작동하는 것 (2026-08 기준)

> 아래는 참고 스냅샷이다.

**운영 규모**: 약 200개 농장 · 1.1만 두 · 누적 이벤트 75만 건 이상 · AI 엔진 6종

**코드 감사로 검증된 "현재 작동" 기능** (`docs/cowtalk-capability-audit-20260625.md`)

| 영역 | 작동하는 것 |
|---|---|
| **AI 어시스턴트 "팅커벨"** | MCP 도구 25개 (조회·기록·추천·분석) · 역할별 접근제어 · 감사로그 자동기록 · 음성 입출력 · 방역모드 자동전환 |
| **방역·역학** | 전국→시도→농장→개체 3단계 드릴다운 · **SEIR 미분방정식 기반 확산 시뮬레이션** · 접촉망 추적 · 역학조사 DB · KAHIS 보고 워크플로 |
| **번식 AI** | 6단계 칸반 파이프라인 · 수정적기 추천(AM-PM) · 발정동기화 4종 프로토콜 자동일정 · 정액 추천 |
| **조기감지** | DSI(질병징후지수) 0~100, 70 이상 경보 |
| **공공데이터** | 이력제(EKAPE) 실연동 · 등급판정 · 경락가격 |
| **수의 임상** | 감별진단 확률 순위 + 근거 + 확인검사 트리 · 처방전 PDF · **휴약기간 자동 계산** · 치료결과 추적 |
| **행정** | 4역할 RBAC · 데이터 내보내기(CSV/XLSX) · 월간 리포트 · 자동화 룰 엔진 |

**정직하게 로드맵인 것**
- 젖소 혈통(종축개량협회)·DHI 정밀 연동 → 현재는 내부데이터 기반 추천(신뢰도 표시)
- 해외 종모우 데이터(CDCB/CRV 등) → 수출 단계 과제
- 역학조사 기상 실연동 일부, 주간 발열 추이 히스토리 적재

> **발표 팁**: "이건 됐고, 이건 로드맵입니다"라고 나누어 말하는 순간
> 나머지 전부의 신뢰도가 올라간다. 심의위원은 "다 된다"는 말을 믿지 않는다.

## 5. 무엇이 다른가 — 3개의 비교축

### vs. 센서 회사 (smaXtec, Allflex, CowManager …)
센서 회사는 **한 목장 안**에서 끝난다. 알람까지가 상품이다.
CowTalk은 알람 위에 **공공데이터·AI·다중역할·행정**을 얹는다.
→ **경쟁이 아니라 계층이 다르다. smaXtec은 CowTalk의 1층이다.**

### vs. 농장관리 소프트웨어 (ERP형)
기록 도구는 사람이 입력해야 살아난다. 그래서 대부분 죽는다.
CowTalk의 데이터는 **센서가 스스로 넣는다.** 사람은 판단만 한다.

### vs. 국가 방역 시스템 (KAHIS 등)
국가 시스템은 **신고된 것**을 다룬다. 신고 전 단계는 공백이다.
CowTalk은 **신고 이전의 생체신호**를 본다.
→ **대체가 아니라 조기 감시망(early warning layer)으로 앞단에 붙는다.**

## 6. 세 가지 가치 — 왜 이것이 공공재인가

| 가치 | 수혜자 | 측정 지표 |
|---|---|---|
| **목장 경제성** | 농가 | 두당 일 마진, 공태일, 수태율, 폐사율 |
| **질병 관리** | 농가 + 수의계 | 조기발견 리드타임, 치료 성공률, 항생제 사용량 |
| **공공성** | 국가·사회 | 전염병 확산 차단, 사육두수↓·생산량 유지, 탄소·분뇨 저감 |

세 번째가 핵심이다. **번식 효율이 오르고 생애수명이 늘면 후보축(육성우)을 덜 키워도 된다.**
같은 우유를 더 적은 소로 생산한다는 뜻이고, 이는 그대로
**사료비 절감 · 분뇨 감소 · 탄소 저감**으로 이어진다.

> 이건 농가 수익 이야기가 아니라 **국가 축산의 총 자원효율 이야기**다.
> 지자체·중앙정부 발표에서 반드시 이 지점을 짚어야 한다.

## 7. 데이터 주권 — 해외 발표에서 가장 먼저 나오는 질문

- 모든 데이터는 **DB를 거친다.** AI가 파이프라인을 우회해 직접 판단하지 않는다 (Data Spine 원칙)
- 모든 AI 도구 호출은 **감사 로그**에 자동 기록된다 (누가·언제·무엇을 조회했나)
- 역할별 접근제어가 **게이트웨이 수준**에서 강제된다 (권한 밖 데이터는 조회 자체가 차단)
- 기억(장기 메모리)조차 **계정 권한 경계 안에서만** 회상된다
- 배포 모델: 국가별 **소버린 인스턴스** — 데이터는 그 나라 안에 남는다 (`03-partner-architecture.md` §5)

> **한 줄 답변**: "데이터는 그 나라 국경 안에 있습니다.
> 우리가 수출하는 것은 데이터가 아니라 **운영체제**입니다."
