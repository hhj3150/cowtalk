## 2. 핵심 소스 텍스트 (NotebookLM에 텍스트 소스로 붙여넣기)

```
# CowTalk v5.0 — 기준 요약 문서 (오디오/비디오 개요 생성용)

## 한 줄 정의
CowTalk은 축산 디지털 운영체제다.
공식: smaXtec 위내센서 + 국가 공공데이터 + AI 해석 + 역할별 액션플랜 = 통합 플랫폼.
smaXtec을 복제하지 않는다. 세계 최고 수준의 센서 위에 세 개의 레이어를 얹는다.

## 왜 필요한가 (문제 정의)
smaXtec의 센서와 알고리즘은 세계 최고 수준(이벤트 정확도 95%+)이지만,
"알람이 왔다"와 "그래서 무엇을 해야 하는가" 사이에 다리가 없다.
발정 알람이 와도 목장주가 혼자 판단해야 하고, 판단의 근거가 되는
이력제·혈통·등급판정·DHI·방역·기상 데이터는 각기 다른 시스템에 흩어져 있다.
또한 축산 행정(역학조사, 방역보고, 수급조절)은 여전히 아날로그에 가깝다.
CowTalk은 이 간극을 메운다: 알람 → 판단 → 추천 → 행동 → 기록이 한 화면에서 끝난다.

## 세 개의 레이어
레이어 1 — 공공데이터 융합: 이력제(EKAPE 실연동), 혈통, 축산물 등급판정, 경락가격,
  DHI, KAHIS, 기상을 개체 단위로 매핑한다.
레이어 2 — CowTalk AI: 데이터 → AI 분석 → 결과 축적 → AI 재강화의 순환 루프.
레이어 3 — 다중 역할·행정 디지털 전환: 같은 데이터를 목장주·수의사·방역관·행정관이
  각자의 관점으로 본다.

## AI 4층 구조
1층 Data Integration — smaXtec 이벤트(신뢰) + 센서 원데이터 + 공공데이터 + 농장기록 → 통합 개체 프로필
2층 Claude AI Interpretation — 통합 프로필을 Claude API가 해석하고 역할별 액션을 생성.
  v4 룰 엔진은 보조 분석과 fallback을 담당(AI가 끊겨도 서비스는 멈추지 않는다).
3층 Role-Based Serving — 4개 역할별 대시보드와 액션플랜
4층 Intelligence Loop — 피드백 → 정확도 추적 → 프롬프트 개선(모델 재학습이 아니라 자기보정 가이던스)

## 현재 규모 (실측 스냅샷, 2026-07-19)
농장 201개 / 소 11,170두 / 센서 장착 11,127두 / 누적 이벤트 757,062건 / AI 엔진 6개.
규모의 유일한 진실은 DB이며, 실시간 집계 API(GET /api/public/stats)가 값을 공급한다.
과거 문서의 "146농장 / 7,000두"는 옛 스냅샷이다.

## 실제로 작동하는 것 (코드 감사로 검증됨)
- 팅커벨 AI: MCP 도구 25개(조회·기록·추천·분석). 역할별 접근제어(RBAC), 감사 로그 자동 기록,
  실시간 스트리밍, 프롬프트 캐싱, 도구 병렬 실행, 출처 기록 의무화(환각 방지), 음성 입력·음성 답변.
- 번식 AI 루프: 6단계 칸반(실DB), 수정 적기 추천, 발정동기화 4종(OVSYNCH/PG/G6G/Double OVSYNCH)
  일정 자동 생성, 번식 KPI(수태율·공태일·분만간격·첫수정일수).
- 방역/역학: 전국→시도→농장→개체 3단계 드릴다운, 전 농장 실좌표 지도,
  확산 시뮬레이션(SEIR 미분방정식, R0·잠복기·감염기간·이동제한 시나리오),
  접촉망 추적(실 이동이력 우선), 역학조사 DB 영속화, KAHIS 보고 상태관리.
- 센서/조기감지: 5분 주기 수집, 조기 질병감지 지수 DSI(0~100, 70 이상 경보).
- 공공데이터: 축산물통합이력정보·등급판정·경락가격 실연동.
- 자동화 룰 엔진: 알람을 행동으로 자동 연결하되, 도구 실행은 반드시 승인 게이트를 경유한다.
  자동화가 승인 체계를 우회하는 경로는 없다.
- 전문가 학습 루프: 수의사·방역관의 대화 속 판단이 곧 고신뢰 학습 레이블이 된다.
  농장주·행정관의 추측은 학습 데이터에서 제외해 오염을 막는다.

## 정직한 한계 (반드시 함께 말할 것)
- 젖소 정액 추천: 추천 엔진은 품종 무관으로 동작하나, 혈통(종축개량협회)·DHI 연동 전까지는
  내부 데이터 기반이며 신뢰도를 화면에 표시한다.
- 역학조사 기상 데이터 일부, 과거 발열 추이 히스토리는 보강 중이다.
- 착유 로봇(Lely A3 + T4C v4.20)은 공개 API가 없어 현재 CSV 업로드 방식이며,
  목장 PC 동기화 에이전트가 예정되어 있다.

## 파일럿과 검증
- 파일럿 목장: 송영신목장(소유자 직영). 소유자는 스마트팜·축산환경 전문가이며 우유공장을 직접 운영한다.
- 운영 루프: 아침 브리핑 → 결정 카드 조치 → 유량·유성분·TMR 기록 → 조치 기록률 → 월간 성과 리포트(두당 일 마진).
- 목표 지자체: 경기도. 파일럿 실측 성과가 제안서의 근거가 된다.
- 환경 축: 휴머스(HUMUS)를 활용한 HBP 시스템(Humus Bedded Pack barn) 기반
  축산환경관리 및 경축순환모델 확립. 적용 축종은 낙농·비육우·육계·양돈.
  (※ "피트모스"라는 표현은 사용하지 않는다.)

## 미래성 — 확장의 축
1) 1개 농장 → 전국 → 국가로 확장되는 구조.
2) 데이터가 쌓일수록 정확해지는 순환: 센서·공공데이터 → AI 분석 → 전문가 레이블 → 프롬프트 자기보정
   → 다음 판단이 개선됨. 모델을 재학습하는 것이 아니라, 감사 가능한 규칙 기반 가이던스로 보정한다.
3) 수출 가능 구조: 한국 특화(공공데이터 커넥터)이되 국가별 어댑터 패턴과 i18n으로 분리 설계.
4) 축산 디지털 주권: 방역 고도화, 전염병 확산 차단, 행정의 아날로그→디지털 전환.

## 3대 가치
목장 경제성(번식성적 향상·질병 조기 대응으로 수익 증가),
질병 관리(위내센서+AI 조기감지로 피해 최소화),
공공성(국가 방역 고도화·확산 차단·축산 디지털 주권).

## 톤 원칙
CowTalk의 목적은 시연이 아니라 실제 목장에 도움이 되는, 사회와 세계에 기여하는 프로그램이다.
과장하지 않는다. 되는 것과 아직 안 되는 것을 구분해 말한다.
```

### 3-A. 표준본 — 맞춤설정 입력란에 그대로 붙여넣기

```
[역할] 당신은 축산·농정 분야 정책 브리핑 내레이터다. 한국어로, 지자체 담당자와
축산 현장 전문가가 함께 듣는 자리에서 설명한다고 가정하라.

[주제] "CowTalk AI의 필요성 · 활용성 · 미래성" — 이 세 축으로 슬라이드를 구성하라.

[분량] 슬라이드 10~12장, 전체 6~8분. 슬라이드 1장당 내레이션 3~5문장.

[슬라이드 구성 — 이 순서를 지켜라]
1. 표지 — "CowTalk: 축산 디지털 운영체제"와 한 줄 정의(smaXtec 센서 + 공공데이터 + AI 해석 + 역할별 액션)
2. 문제 — 센서는 세계 최고인데 "알람과 행동 사이에 다리가 없다". 데이터는 흩어져 있고 행정은 아날로그다.
3. 해답의 공식 — 세 개의 레이어(공공데이터 융합 / CowTalk AI / 다중 역할·행정 전환)
4. AI 4층 구조 — 데이터 통합 → Claude 해석 → 역할별 서빙 → 지능 루프
5. 활용 ①: 목장주 — 발정 알람에서 수정 적기·정액 추천·기록까지 한 화면에서 끝나는 번식 루프
6. 활용 ②: 수의사 — 감별진단, 치료 결과 추적, 전문가 판단이 곧 학습 레이블이 되는 구조
7. 활용 ③: 방역관 — 전국→시도→농장→개체 드릴다운, SEIR 확산 시뮬레이션, 역학조사·KAHIS 보고
8. 활용 ④: 행정관 — 수급 조절과 축산 행정의 아날로그→디지털 전환
9. 지금 실제로 돌아가는 규모 — 농장 201개, 소 11,170두, 센서 11,127두, 누적 이벤트 757,062건
10. 정직한 경계 — 아직 보강 중인 것(젖소 혈통·DHI 연동, 기상 데이터 일부, 착유로봇 자동 연동)
11. 미래성 — 데이터가 쌓일수록 정확해지는 순환, 1농장→전국→국가, 국가별 어댑터로 수출 가능한 구조
12. 마무리 — 3대 가치(목장 경제성 / 질병 관리 / 공공성)와 파일럿(송영신목장 → 경기도)

[화면 텍스트 규칙]

- 숫자는 크게, 단위를 붙여서(예: 농장 201개 / 11,170두 / 757,062건).
- 아이콘·다이어그램은 소·센서·지도·순환 화살표 계열로. 사람 사진 스톡 이미지는 피하라.

[내레이션 규칙]
- 존댓말, 담백하고 단정한 브리핑 톤. 감탄사·광고 문구·"혁신적인" 같은 형용사를 쓰지 마라.
- 전문용어는 처음 나올 때 한 문장으로 풀어라 (예: "DSI, 즉 조기 질병감지 지수").
- 영어 약어는 한국어 독음으로 읽어라 (SEIR → "에스이아이알 모형", KPI → "핵심 성과 지표").

[사실 규칙 — 가장 중요]
- 제공된 소스에 있는 수치와 기능만 말하라. 소스에 없는 도입 농가 수, 매출, 절감률,
  수태율 향상 퍼센트, 폐사율 감소 수치를 절대 생성하지 마라.

- 10번 슬라이드(정직한 경계)를 생략하지 마라. 이 자료의 신뢰도는 여기서 나온다.
- "피트모스"라는 표현을 쓰지 말고, 환경 축은 "휴머스를 활용한 HBP 시스템"으로 부르라.
- CowTalk을 smaXtec의 대체재가 아니라 그 위에 얹는 확장 레이어로 설명하라.
```

### 3-B. 단축본 — 입력란 글자수가 부족할 때

```
한국어 브리핑 톤. 청중은 지자체 담당자와 축산 전문가. 슬라이드 10~12장, 6~8분.
구성: ①표지·한줄정의 ②문제(알람과 행동 사이에 다리가 없다) ③3개 레이어
④AI 4층 구조 ⑤~⑧역할별 활용(목장주 번식루프 / 수의사 감별진단·학습루프 /
방역관 드릴다운·SEIR 확산 시뮬레이션 / 행정관 디지털 전환) ⑨현재 규모
⑩정직한 한계 ⑪미래성(데이터 순환·전국 확장·수출 구조) ⑫3대 가치와 파일럿.

⑩번 한계 슬라이드는 반드시 포함. "피트모스" 대신 "휴머스 기반 HBP 시스템".
```

```
③누가 어떻게 쓰는가 — 목장주·수의사·방역관·행정관 4역할이 같은 데이터를 각자 관점으로
④지금 어디까지 왔나 — 실측 규모와 파일럿 ⑤아직 안 되는 것 ⑥앞으로 — 데이터가 쌓일수록
정확해지는 순환, 전국·국가 단위 확장, 국가별 어댑터로 수출 가능한 구조
```

## 5. 변형 프롬프트 (청중별)

**A. 경기도 정책 담당자용 (5분, 행정 중심)**
```
위 구성에서 ⑤~⑥(목장주·수의사)을 각 1장으로 줄이고, 방역관·행정관 파트를 각 2장으로 늘려라.
경기도 파일럿(송영신목장)의 운영 루프 — 아침 브리핑 → 결정 카드 조치 → 기록 → 월간 성과 리포트 —
를 한 장으로 보여주고, 성과는 "측정 중인 지표"로 표현하라. 총 8장, 5분.
```

**B. 목장주·조합 대상 (4분, 현장 중심)**
```
정책·아키텍처 설명을 최소화하고, 하루의 흐름으로 재구성하라.
아침 브리핑 → 발정 알람 → 수정 적기와 정액 추천 → 조치 기록 → 임신감정 결과 피드백 →
다음 판단이 더 정확해짐. 전문용어는 최대한 우리말로. 총 7장, 4분.
```

**C. 투자·심사용 (7분, 확장성 중심)**
```
문제-해법-검증-확장 순서로 재구성하라. 검증 파트에서는 코드 감사로 확인된
"실제 구현된 기능"과 "보강 중인 기능"을 명확히 나눠 제시하라.
확장 파트에서는 국가별 어댑터 패턴과 i18n 분리 설계, 데이터 순환 구조가
왜 시간이 갈수록 유리해지는지를 설명하라. 총 11장, 7분.
```
